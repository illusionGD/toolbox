# 网页自动化测试

入口：**开发工具 → 网页自动化测试**。使用 Playwright Core 驱动本机 Microsoft Edge 或 Google Chrome，打开独立浏览器会话；无需额外下载 Chromium。视频编码使用应用自带的 ffmpeg。

## 录制与复用

1. 在「录制用例」填写名称、录制入口 URL 和环境根地址，设置浏览器宽高；可开启「同时录制视频」并选择 WebM 或 MP4。
2. 点击「开始新录制」，在打开的浏览器里操作。需要登录的用例从登录页开始，不沿用个人浏览器的登录状态。
3. 回到工具页点击「结束录制」。最后的输入会先排空，浏览器关闭后视频完成封装；选择 MP4 时会等待格式转换。切换工具页或刷新不会丢失主进程中的会话。
4. 用例会自动保存为数据保存目录下的 `webtest/last-flow.json`；开始新录制前，应导出需要长期保留的用例。
5. 选择步骤可在它后面插入检查点；也可以编辑动作、CSS 定位、输入值、页签、iframe 链等字段。
6. 在「回放测试」填写目标环境根地址并开始回放。回放不注入录制脚本、不录视频。

录制时跳转到环境根目录以外的页面，不会判定失败或结束会话：仅暂停对应页签的操作记录，返回范围内后自动继续。其他仍在范围内的页签可以正常录制；外部页签的打开/关闭不会生成无效用例步骤。视频仍连续录制。

浏览器宽高按**页面可视区域**计算（CSS 像素，不含地址栏和窗口边框），默认 **1280 × 720**；宽度范围 320–3840，高度范围 240–2160。录制尺寸保存在用例的 `viewport` 中，导入、导出及独立脚本都沿用该尺寸。回放默认开启「使用用例尺寸」，关闭后可设置本次回放的宽高，不修改原用例。实际回放尺寸会写入报告。视频格式及录制/回放尺寸设置自动保留。

用例标题栏的「清空步骤」可在录制/回放结束后删除全部步骤及执行结果，保留用例信息和环境配置。确认前可以取消，确认后自动保存为空用例。

每个新录制步骤保存与上一步操作的间隔 `delayBeforeMs`（毫秒，首步为 0）。回放和导出的 JS/TS 脚本会在非输入步骤前等待该间隔；输入内容仍合并为一次填充，跳过输入步骤自身的等待，输入结束到下一次点击的间隔仍保留。步骤列表可查看间隔，编辑器可调整非输入步骤的间隔（最多 24 小时）。等待不占用单步操作超时，可通过「停止」立即取消。旧用例缺少此字段时按 0 处理，原始节奏需要重新录制或手动填写。

### 地址如何映射

| 项目 | 示例 |
| --- | --- |
| 录制入口 | `https://test.example.com/app/login?from=qa#/start` |
| 录制环境根地址 | `https://test.example.com/app/` |
| 用例保存的路径 | `./login?from=qa#/start` |
| 回放环境根地址 | `https://staging.example.com/product/` |
| 实际回放地址 | `https://staging.example.com/product/login?from=qa#/start` |

环境根地址按目录处理，不能包含查询参数、hash 或 URL 凭据。用例内地址不能跳出根目录；支持切换域名、端口与部署目录。页面操作引发的普通跳转、SPA 路由变化录为地址检查点，回放必须实际跳到对应页面。

## 定位和检查点

定位优先尝试测试属性、稳定 `id`、`name`、业务属性、`type` / `role` 等非文案属性，以及排除状态/哈希后的类名。单个特征不唯一时组合属性，或利用稳定祖先锚点（例如 `[data-testid="login-form"] button.submit`）。使用后代关系，不依赖固定父子层级，插入包装节点或调整兄弟顺序后仍能定位。

没有稳定的唯一特征时，自动使用父子路径和必要的 `nth-of-type` 结构定位兜底，并验证其在录制页面中唯一匹配目标。步骤标记为「结构定位」，可正常回放和导出；iframe 和 Shadow DOM 的结构定位也会保留此标记。结构变化仍可能使定位失效，可在编辑器补充稳定 CSS，或为目标配置 `data-testid` 后重新录制。只有结构路径也无法唯一定位时，才标记「待补充定位」并在回放该步前停止。仍不使用文案、placeholder、label、accessible name 或 XPath。旧用例可继续导入。

结构兜底会保留元素的稳定类名/属性，并回溯到唯一的稳定祖先；没有锚点时保留到文档根的完整路径。不会仅因为录制当时唯一就生成 `li:nth-of-type(7)` 这样的裸序号，避免后来出现的调试面板、其他列表造成多匹配。旧用例缺失的祖先信息无法自动恢复，需在步骤编辑器补充目标类名和所属容器，或重新录制；多匹配仍会停止，不自动选取第一个元素。

支持点击、双击、右键、输入、勾选、按 `option.value` 选择、常用快捷键、滚动、iframe、开放 Shadow DOM、页面新开/关闭。Enter 引发的合成点击不重复录制。

动作成功只代表操作完成。验证业务结果需添加检查点：元素可见/隐藏、输入值、勾选状态、页面地址。定位失败、超时、检查点失败或导航 HTTP 错误会立即停止，列表标出失败步骤，后续步骤保持待执行。失败时保留浏览器现场供检查，下次任务开始时关闭旧窗口。

视频暂存于**缓存目录**的 `webtest/videos/<会话 ID>/`，使用设置页当前配置的缓存路径。录制前开启「同时录制视频」，选择 **WebM（默认）** 或 **MP4（H.264）**，每个页签各生成一个所选格式的视频。视频尺寸跟随录制页面；遇到奇数宽高时向上补齐为偶数，不裁切页面内容。结束录制后，在步骤列表上方的「录制视频」中播放或定位文件。「保存视频」按原格式复制到所选位置并保留缓存原件，不能通过改扩展名转换格式；「删除视频」确认后只删除列表中的视频原件，不影响另存的副本。清理缓存会删除尚在缓存内的视频，需要长期保留时请先保存。

MP4 在结束录制时使用应用自带编码器转换，完成前显示「正在停止并保存产物」。转换成功后移除中间 WebM；转换失败则提示原因并保留原始 WebM 和操作步骤，可继续导出、回放用例或保存原视频。

视频列表兼容旧版数据目录 `webtest/artifacts/<会话 ID>/` 中的视频，不自动移动旧文件。编辑步骤、回放、清空用例不删除视频；重启后读取当前缓存目录和旧版目录。录制中的视频在封装完成后显示，可手动刷新列表。失败截图和 `report.json` 继续位于数据保存目录的 `webtest/artifacts/<会话 ID>/`，在「测试报告与截图」中定位。视频独立保存，不包含在导出的 JSON / JS / TS 用例中。

## 导入 / 导出

- JSON：带版本号的 `toolbox.webtest` 数据，可检查或修改后导入。
- JS / TS：可独立运行的 Playwright 脚本，内嵌相同数据区，可重新导入。
- 导入只解析数据，不执行脚本。仅支持本工具导出的脚本格式；手工新增脚本逻辑不会变成录制步骤。修改可导入数据时编辑标记之间的 JSON。
- 最大文件 5 MB、最多 5000 步；版本、动作、必填字段、CSS 引擎及页签顺序均在主进程校验。

独立脚本的使用方式：

```powershell
npm install playwright-core@1.63.0
node ./login.js https://staging.example.com/app/
# TypeScript 可用 tsx 执行，或者经 TypeScript 编译后执行
npx tsx ./login.ts https://staging.example.com/app/
```

默认使用 Edge；环境变量 `WEBTEST_BROWSER=chrome` 可切换 Chrome，`WEBTEST_HEADLESS=1` 开启无头模式，`WEBTEST_TIMEOUT=10000` 设置单步超时（100–120000 毫秒）。失败退出码为 1，报告及截图保存在脚本运行目录下的 `webtest-results/`。

## 当前边界

- 输入值直接保存在用例中，请使用专用测试账号；用例和视频都可能包含测试数据。
- 跨域页面仅暂停操作录制，不保存外站操作，也不自动还原外站交互；返回原环境会产生地址检查点，回放仍需实际满足该检查点。暂不支持文件上传映射、拖拽、Canvas 内坐标动作和原生 alert/confirm/prompt 回放。可检测到的不支持动作会明确留在步骤中，回放在该步停止；录制范围内的原生弹窗会取消并停止录制，避免浏览器挂起。
- 浏览器地址栏、后退/前进按钮不属于页面 DOM 操作。录制期间通过页面内链接导航；手工地址栏导航会成为检查点，必要时在编辑器将其改为「打开页面」。
- 旧用例的 CSS 结构、业务类名/属性、查询参数内的业务 ID 仍可能随环境变化；这些值可在步骤编辑器中维护。该版本不做图像差异或页面文案的自动断言。
- 安装包配置已包含 Playwright 解包资源；需在目标 Windows 环境安装所选的 Edge 或 Chrome。

## 开发验证

### 让 AI 排查和修复

重启应用后，打开「AI 助手」，将工具模式设为「询问」或「自动」。AI 与工具页共用当前用例和浏览器现场。例如：

> 检查当前网页测试失败的步骤，查看 CSS 匹配到哪些元素，预览修复后保存，并在我提供的测试环境根地址回放验证。

已提供 11 个工具：`webtest_status`、`webtest_read_steps`、`webtest_inspect`、`webtest_patch_steps`、`webtest_import`、`webtest_export`、`webtest_record`、`webtest_replay`、`webtest_wait`、`webtest_stop`、`webtest_videos`。

AI 可读取失败步骤和实际页签，检查匹配元素的类名、稳定属性及候选 CSS，按步骤 ID 预览/保存修改。步骤读取默认隐藏输入值；修复保存使用版本校验，避免覆盖你刚编辑的内容。保存、导入和开始新录制会走确认卡；“自动”下这些操作仍需确认。回放会真实执行页面动作，只有回放通过才算修复验证成功。

AI 的 `webtest_record` 支持 `videoFormat`（`webm` / `mp4`）和 `viewport: { width, height }`；`webtest_replay` 的可选 `viewport` 仅覆盖本次回放尺寸。`webtest_status` 返回实际使用的尺寸。

取消 AI 对话会停止该轮启动的回放；已成功启动的操作录制交由用户继续，结束时点击工具页按钮或让 AI 调用停止工具。失败后保留的浏览器可供只读检查；已经关闭的页面无法凭空恢复 DOM。工具单次等待最多 10 秒、每轮聊天最多 8 个工具轮次，长用例可在下一轮继续查询。

维护规范见 [网页测试 skill](../.claude/skills/webtest/SKILL.md)。应用内工具描述直接提供调用指导，`.claude` skill 用于项目开发维护，不会自动注入聊天上下文。

### 命令

```powershell
pnpm typecheck
pnpm exec eslint .
pnpm build
pnpm verify:webtest
pnpm verify:webtest:ui
pnpm verify:ai
```

`verify:webtest` 使用本机 Edge 无头浏览器和本地测试服务器，验证真实录制/回放、跨环境和文案变化、iframe/Shadow DOM/新页签、JSON/JS/TS 往返与独立执行、失败停止、取消、视频/截图以及生产 ffmpeg 适配器。

`verify:webtest:ui` 依赖最新 `pnpm build` 产物，用隐藏 Electron 窗口验证真实 preload/IPC 下的导入、编辑、检查点、导出、刷新恢复和窗口布局；仅文件对话框的用户选择及与本功能无关的窗口/桌宠状态由验证桩提供。产物统一保存在已忽略的 `out-tbverify/`。
