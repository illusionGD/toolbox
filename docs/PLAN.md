# Toolbox 桌面工具箱 · 开发规划（Plan）

> 本文档只列**大致清单**与**优先级**，不做详细设计。每个功能的细节在开发前单独讨论。
> 约定：**每完成一个功能即停下，交付 review + debug 后再继续**。

---

## 1. 技术栈与约定

- **框架**：Electron + Vue 3 (`<script setup lang="ts">`) + TypeScript
- **构建/包管理**：Vite + pnpm（Electron 侧用 electron-vite 或 vite-plugin-electron，开发时确认）
- **状态**：Pinia（setup store）
- **UI**：naive-ui + `@vicons/ionicons5`
- **样式**：TailwindCSS + SCSS（全局 tokens/theme 走 `assets/styles`）
- **规范**：ESLint + Prettier，遵循 `.claude/rules` 下两份规范
- **主题**：默认黑 + 紫色调，预留自定义主题色能力

### 进程/目录约定（开发前细化）
- `electron/`（主进程 main、预加载 preload、IPC 通道）
- `src/`（渲染进程，遵循 vue3 项目结构规则：views / components / stores / composables / services / utils / types / constants / assets）
- 重活（图片/视频/字体/文件处理）走**主进程或 worker**，通过 IPC 暴露，避免阻塞 UI

## 4. 账号与计费规划（当前只预留，不接后端）

> 结论：账号/计费是**横切能力**，不是末尾的一个孤立功能。现在花很小成本把"接缝"留好，等后端就绪时只填实现，不改各工具页面。

### 4.1 现在就做（成本极低的预留）

1. **权限门面（唯一入口）**：所有功能是否可用都经过一个统一判断，例如 `useEntitlement()` / `can(featureKey)`。
   - 当前实现恒返回"允许"（本地 mock），后端接入后换实现即可，**调用方不改**。
2. **功能标识（featureKey）**：每个工具在注册元信息里带 `featureKey` 与 `tier`（如 `free` / `pro`），
   现在全部标 `free`，后续把要收费的改成 `pro` 即可，无需改页面逻辑。
3. **账号 store（占位）**：`stores/user.ts` 定义 `user / token / isLoggedIn / plan` 结构与
   `login / logout / refresh` action，内部先走 mock，UI 可正常联动（如头像/登录态）。
4. **服务层预留**：`services/` 下留 `auth`、`billing` 模块（接口签名先定、实现留空或 mock），
   统一 HTTP 客户端（拦截器挂 token、401 处理）先搭好但不指向真实后端。
5. **UI 占位**：顶部账号入口（未登录=登录按钮，登录后=头像菜单）；付费墙组件 `<ProGuard>`
   （包住需付费的操作区，free 阶段透明放行），避免后期到处补弹窗。
6. **配置开关**：`.env` 加 `VITE_ENABLE_ACCOUNT`、`VITE_API_BASE` 等，默认关闭/指向 mock，
   一键切换真实后端。

### 4.2 后端就绪后再做（P7）

- 接真实登录/注册/OAuth、token 刷新与安全存储（Electron safeStorage）。
- 套餐/额度/订单，付费墙真正拦截，功能级权限从服务端下发。
- 用量上报（与首页"使用统计"打通，可作为计费依据）。

### 4.3 预留原则

- **调用方无感**：工具页面永远只问"我能用吗"，不关心免费/付费、是否登录。
- **默认全放行**：预留代码在无后端时不影响任何现有功能的使用。
- **可开关**：所有账号/计费能力受 env 开关控制，随时可整体关掉。

## 6. 工作方式

- 严格按优先级从 P0 往下推进。
- **每完成一个编号功能就暂停**，等待你 review / debug 通过后再继续下一个。
- 每个功能开发前，先就该功能的交互与参数细节做一轮讨论。
- 需求变更或新增工具，追加到对应 Px 分组，不打乱正在进行的功能。

### 每个功能的交付标准（Definition of Done）

一个功能"完成"必须同时满足：

1. 功能可用、通过 review 与 debug。
2. 代码经 ESLint + Prettier 格式化，符合 `.claude/rules` 规范。
3. **随功能写一份 skill**，放在 `.claude/skills/<skill-name>/SKILL.md`，用于后续维护。内容包含：
   - 该功能的用途与入口（对应 view / 路由 / 菜单位置）；
   - 关键实现与依赖（涉及的 IPC 通道、主进程处理、第三方库如 sharp/ffmpeg）；
   - 参数与配置项说明、边界与已知限制；
   - 常见问题 / 调试要点 / 维护注意事项。
   - 基础框架（P0）的公共能力（IPC 封装、权限门面、通用组件等）也各写对应 skill。

## 7. 已确认的关键决策

1. **Electron 集成**：采用 **electron-vite**（三段式 main/preload/renderer，HMR + TS 完善）。
2. **重处理位置**：**主进程** 处理（图片用 sharp、媒体用 ffmpeg），通过 IPC 暴露给渲染进程；需处理 native 依赖打包。
3. **ffmpeg**：**接受打包**（用 ffmpeg-static 之类），媒体工具开箱即用，接受安装包体积增大。
4. **自动更新 / 多语言**：暂不实现，代码留接口，后续需要再讨论。
