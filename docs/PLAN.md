# Toolbox 桌面工具箱 · 开发规划（Plan）

> 本文档只列**大致清单**与**优先级**，不做详细设计。每个功能的细节在开发前单独讨论。
> 约定：**每完成一个功能即停下，交付 review + debug 后再继续**。

---

## 1. 技术栈与约定

- **框架**：Electron + Vue 3 (`<script setup lang="ts">`) + TypeScript
- **构建/包管理**：Vite + pnpm（Electron 侧用 electron-vite 或 vite-plugin-electron，开发时确认）
- **状态**：Pinia（setup store）
- **UI**：naive-ui + `@vicons/ionicons5`
- **样式**：TailwindCSS + SCSS（全局 tokens/theme 走 `assets/styles`）
- **规范**：ESLint + Prettier，遵循 `.claude/rules` 下两份规范
- **主题**：默认黑 + 紫色调，预留自定义主题色能力

### 进程/目录约定（开发前细化）

- `electron/`（主进程 main、预加载 preload、IPC 通道）
- `src/`（渲染进程，遵循 vue3 项目结构规则：views / components / stores / composables / services / utils / types / constants / assets）
- 重活（图片/视频/字体/文件处理）走**主进程或 worker**，通过 IPC 暴露，避免阻塞 UI

5. **通用能力**：IPC 封装、文件选择/拖拽、通用文件列表组件、任务/进度组件、设置页骨架
   - **存储路径设施**（2026-09-02 追加）：设置页给出「数据缓存目录」（默认系统临时目录，可改、可清空）与「数据保存目录」（默认安装目录下 `data`，可改且**改后迁移数据**，不可写时自动回退并提示）；后续所有落盘功能只经 `storage/paths.ts` 取路径，应用状态（主题 / 各工具配置 / 使用统计）从 localStorage 搬进 `<dataDir>/app-state.json`

### P6 · AI 赋能

23. **AI 接入**（用户 2026-09-02 提出六条需求，按「一个功能停一次 review」拆两轮）

- **23a 对话**（已完成）：兼容各厂商 + 多份「厂商+模型+自定义名称」配置选其一 + 配置在设置页 + 首页右上角入口开对话弹窗（流式 / 传图 / 多会话持久化 / 取消）+ 模型清单写死。用 **Vercel AI SDK 钉死 `ai@6`**（`ai@7` 要 Node≥22，Electron 33 只有 Node 20.18.3），四个包覆盖九个厂商；网络调用全在主进程，**API Key 存 `<userData>` 而配置存 `<dataDir>`**。见 skill ai-chat
- **23b 工具调用**（已完成）：让 AI 调现有的 `file.*/image.*/video.*/audio.*/font.*/excel.*` 等能力，落成 **13 个工具**（读 8：`list_files`/`probe_image`/`probe_video`/`probe_audio`/`probe_font`/`probe_excel`/`read_text_file`/`storage_info`；写 5：`compress_images`/`convert_video`/`convert_audio`/`rename_files`/`write_text_file`）。确认策略按用户 2026-09-20 的要求更新：**只读直接跑，询问模式逐次确认写工具，自动模式直接执行全部写工具（包括覆盖与重命名）**。开关是对话窗口里的 **`关闭 / 询问 / 自动` 三态**下拉（「关闭」不下发 `tools`），对下次发送生效；网页测试及插件工具同样遵循该策略，底层参数校验与能力授权继续生效。确认 UI 是**消息流里的内联卡片**（作为记录留在会话里）。**没有删除、没有 shell、没有网络抓取**，返回值一律封顶。见 skill ai-tools
- **23c 对话记录渲染 markdown**（已完成）：推翻 23a 那条「只切围栏代码块」的边界，**选加依赖而不是 `v-html`**——`marked` **只用 `lexer()`** 拿 token，中间落一层纯对象节点树，再由自己的 `h()` 映射出 Vue 节点，**全程零 `v-html`**。三条安全硬规则都在纯函数层（裸 HTML 按字面文本输出 / 只有 `http|https|mailto` 进 `a` / **永不产出 `img`**，远端图片退化成可点链接），CSP 只当第二道防线；顺手补上全仓库缺失的 `will-navigate`（外链交给系统浏览器，窗口不会被导航走）。用户拍的四条：**只助手消息**渲染（用户消息仍是 `pre-wrap` 纯文本）、**只高亮已闭合的围栏**（`n-code` + `n-config-provider :hljs`，hljs core + 15 种语言按需注册）、**CSP 不放开**、**历史全量渲染 / 实时流块级增量**（切点避开未闭合围栏与松散列表，定稿块 memo，`FLUSH_MS=64` 合帧，**停流即换成全量结果**当安全绳）。另一条硬规则：**渲染是派生物**，节点树不落盘、不进 `history`、不跨 IPC——落盘与上下文永远只走原文 markdown（用户要的「保存原有格式、省 token」）。见 skill ai-markdown
- **23d 最小化按钮**（已完成）：用户 review 提的一条「ai对话框加个最小化按钮」。顶栏窗控从 `📌 / ✕` 变成 `📌 / ─ / ✕`。**三个窗控里只有关闭有 DOM API**（`window.close()`）；DOM 的 `window` 没有 minimize，而这个窗口里 `window.api.window.*` 闭包的是**主窗口**，所以最小化只能像置顶那样自己走一条 `ai:minimizeWindow`。真 Electron 探针量过「最小化会不会把窗口位置写坏」，结论是**不会、也不需要守卫**（最小化只触发 `move`/`minimize`，不触发落盘用的 `moved`/`resized`），故没写投机代码。见 skill ai-chat

### P8 · 桌宠

26. **桌宠**（用户 2026-09-05 提出七条需求：切换后隐藏工具箱右下角出现桌宠 / 可以是图·spine·live2d / 五种动画状态与三种资源的映射且未配置的回落到默认 / 没配资源用 logo / 点击弹「设置·AI 对话·打开 app」三个按钮 / 可配 AI 与 AI 头像且桌宠 AI 能调工具 / 可设待机对话，随机播放或按用户 prompt 由 AI 生成。用户原话：「总之桌宠算是整个工具的小精灵，拥有整个 app 的控制权」）

- 用户拍定的两条：**先做图 + spine，live2d 后置**（仓库里没装任何 live2d 库，`spine-pixi-v8` 与 `pixi.js` 已在依赖树里）；**按资源类型分 4 段，每段完成即停下 review**。
- **26b / 26c / 26d 按用户要求推后**（2026-09-11 原话「桌宠剩下功能先不做，先优化」），先做 P0-5 那条追加的「关闭行为与托盘 + 入口整理」。
- **26a 窗口与图片资源**（已完成，经四轮 review 返工）：独立的无边框透明常驻小窗（`?pet=1` 是继 `?ai=1` 之后的第三个分叉，**不新增 rollup 入口**）+ 图片资源 + 五种动画状态 + 手写拖拽 + **右键**菜单六项（设置 / AI 对话 / 打开 app / **隐藏桌宠** / 退出桌宠 / 退出 app，外加一块**能实时拖着调大小**的输入框 + 滑块，**滑块单独占一整行**：菜单才 208px 宽，和输入框挤一行时轨道只剩一百来像素，`64→512` 拖一格就是好几个 px）+ 设置页 + **标题栏 logo 上的切换入口** + 启动恢复。三条硬规则：**桌宠不许成为唯一出口**（主窗口是 `hide()` 的、桌宠 `skipTaskbar`，所以 `close` 一律拦成「退出桌宠模式」，否则用户被锁在没有界面的进程里；同一条规则也管着「隐藏」——**托盘图标建不起来就拒绝隐藏**，而空图标的 `new Tray()` 在 Windows 上不抛异常，可用性必须自己 `isEmpty()` 查）、**状态兜底是纯函数**（`resolvePetVisual` 三级回落，可断言）、**不动 CSP**（图片走已放行的 `data:`、26b 的 spine 走 `blob:`，`tb-media:` 那条白名单不为桌宠而扩）。**两个窗口的寿命各自独立**（review 定的）：桌宠开着时主窗口的 `close` 拦成 `hide()`，真要整个退出走菜单里的「退出 app」。拖拽必须手写（`-webkit-app-region: drag` 分不清点击与拖拽，也拿不到「拖拽中 / 放下」两个动画态），且必须**「起始 bounds + 绝对位移」**（每帧写位置会回灌 `move`，增量累加会漂）；**写位置只能 `setBounds` 且显式带宽高，绝不能 `setPosition`**——非整数缩放（本机 1.25）下探针量到 `setPosition` 连打 120 次会把 `160×160` 撑成 `296×256`，而渲染层是贴底布局，窗口一路长高精灵就一路下移，「拖拽中图片会下移」和「宽高越来越大」是同一个 bug 的两副面孔。同理 `getBounds()` 的宽高不可信（160 的窗口回 161），主进程一律用纯函数 `petWindowSize()` 现算。菜单靠**窗口临时放大**，精灵锚在右下角所以展开时它一动不动。**置顶要周期性抢回来**（第四轮 review 的 bug「一录屏桌宠就不见了」）：`alwaysOnTop` 只决定「在哪一层」，**层内后来者在前**，会议软件共享屏幕那条置顶悬浮工具条就是那个后来者，靠 2s 一次 `moveTop()` 抢回（不抢焦点、不动几何，都是探针量过的）。见 skill desktop-pet
- **26b spine**（待开）：复用 `useSpine.ts`，新增 `pet:readAsset` 走 Blob + objectURL；spine 模式下 `PetStateMap` 的值是**动画名**而不是路径，兜底函数一行不改；设置页要能列出 skeleton 里的动画名供下拉选
- **26c live2d**（待开）：**先探针再选型**。要量：包体、是否需要 CDN（本仓库 CSP 禁）、能不能跑在 pixi v8 上（`pixi-live2d-display` 主流版本钉的是 pixi v6/v7，很可能与现有 v8 冲突——这是最大未知数）
- **26d 桌宠 AI + 待机对话**（待开，需求 6、7）：复用主进程整套 AI 栈（`runChat` + 13 个工具，一行不改）；**桌宠的内置 prompt 必须进 `electron/shared/prompts.ts`**（#23 review 拍的「全仓库唯一出处」）。**需求 6 的「AI 头像」已在 26a 的 review 轮里交付**（`pet` 配置里的 `aiAvatarRef`，设置页可选、AI 窗口助手气泡用它，留空回落到 logo），这一段只剩「桌宠 AI」与「待机对话」

## 4. 账号与计费规划（当前只预留，不接后端）

> 结论：账号/计费是**横切能力**，不是末尾的一个孤立功能。现在花很小成本把"接缝"留好，等后端就绪时只填实现，不改各工具页面。

### 4.1 现在就做（成本极低的预留）

1. **权限门面（唯一入口）**：所有功能是否可用都经过一个统一判断，例如 `useEntitlement()` / `can(featureKey)`。
   - 当前实现恒返回"允许"（本地 mock），后端接入后换实现即可，**调用方不改**。
2. **功能标识（featureKey）**：每个工具在注册元信息里带 `featureKey` 与 `tier`（如 `free` / `pro`），
   现在全部标 `free`，后续把要收费的改成 `pro` 即可，无需改页面逻辑。
3. **账号 store（占位）**：`stores/user.ts` 定义 `user / token / isLoggedIn / plan` 结构与
   `login / logout / refresh` action，内部先走 mock，UI 可正常联动（如头像/登录态）。
4. **服务层预留**：`services/` 下留 `auth`、`billing` 模块（接口签名先定、实现留空或 mock），
   统一 HTTP 客户端（拦截器挂 token、401 处理）先搭好但不指向真实后端。
5. **UI 占位**：顶部账号入口（未登录=登录按钮，登录后=头像菜单）；付费墙组件 `<ProGuard>`
   （包住需付费的操作区，free 阶段透明放行），避免后期到处补弹窗。
6. **配置开关**：`.env` 加 `VITE_ENABLE_ACCOUNT`、`VITE_API_BASE` 等，默认关闭/指向 mock，
   一键切换真实后端。

### 4.2 后端就绪后再做（P7）

- 接真实登录/注册/OAuth、token 刷新与安全存储（Electron safeStorage）。
- 套餐/额度/订单，付费墙真正拦截，功能级权限从服务端下发。
- 用量上报（与首页"使用统计"打通，可作为计费依据）。

### 4.3 预留原则

- **调用方无感**：工具页面永远只问"我能用吗"，不关心免费/付费、是否登录。
- **默认全放行**：预留代码在无后端时不影响任何现有功能的使用。
- **可开关**：所有账号/计费能力受 env 开关控制，随时可整体关掉。

## 6. 工作方式

- 严格按优先级从 P0 往下推进。
- **每完成一个编号功能就暂停**，等待你 review / debug 通过后再继续下一个。
- 每个功能开发前，先就该功能的交互与参数细节做一轮讨论。
- 需求变更或新增工具，追加到对应 Px 分组，不打乱正在进行的功能。

### 每个功能的交付标准（Definition of Done）

一个功能"完成"必须同时满足：

1. 功能可用、通过 review 与 debug。
2. 代码经 ESLint + Prettier 格式化，符合 `.claude/rules` 规范。
3. **随功能写一份 skill**，放在 `.claude/skills/<skill-name>/SKILL.md`，用于后续维护。内容包含：
   - 该功能的用途与入口（对应 view / 路由 / 菜单位置）；
   - 关键实现与依赖（涉及的 IPC 通道、主进程处理、第三方库如 sharp/ffmpeg）；
   - 参数与配置项说明、边界与已知限制；
   - 常见问题 / 调试要点 / 维护注意事项。
   - 基础框架（P0）的公共能力（IPC 封装、权限门面、通用组件等）也各写对应 skill。

## 7. 已确认的关键决策

1. **Electron 集成**：采用 **electron-vite**（三段式 main/preload/renderer，HMR + TS 完善）。
2. **重处理位置**：**主进程** 处理（图片用 sharp、媒体用 ffmpeg），通过 IPC 暴露给渲染进程；需处理 native 依赖打包。
3. **ffmpeg**：**接受打包**（用 ffmpeg-static 之类），媒体工具开箱即用，接受安装包体积增大。
4. **自动更新 / 多语言**：暂不实现，代码留接口，后续需要再讨论。

## 8. Toolbox 插件系统实施计划

目标：外部开发者和 AI 使用同一套插件规范扩展工具页面与命令，无需修改 Toolbox 源码或重新打包。实现本地插件开发、分享与宿主能力扩展；插件市场已按用户要求取消。

### 优先级与状态

- **P0**：首个插件可运行所必需的契约、隔离、授权和管理能力。
- **P1**：首版完整开发体验，包括自定义页面、AI 接入、开发预览与回滚。
- **P2**：受控网络、更多宿主能力与本地 MCP/受信任扩展；在线市场取消，普通插件仍不开放任意 shell。
- 状态：`待开始`、`进行中`、`已完成`、`已取消`；只有实现与对应验证完成后才标记已完成。

### 已确定的技术约定

1. 插件包含 `manifest.json`、预构建 JavaScript、可选 HTML/CSS/资源。发布包为 ZIP 格式的 `.tbplugin`，安装不执行生命周期脚本，不在线安装 npm 依赖。
2. 插件以稳定 SDK 调宿主能力；普通插件不拥有 Node、Electron、任意 IPC、宿主配置或 AI 密钥。页面和 AI 共用命令入口。
3. 插件代码在隔离的 Chromium 沙箱运行，不直接 `require` / `import` 进主进程；普通 Node Worker/子进程不作为权限沙箱。
4. 插件声明能力，宿主执行每次授权校验。安装/启用、允许 AI 调用、文件与网络授权分别管理；不能依赖插件自报只读属性决定写入授权。
5. 插件包、持久数据、缓存分别管理，使用现有 `dataPath` / `cachePath`，兼容数据目录迁移。安装更新不覆盖插件用户数据。
6. 新增代码遵循 `.claude/rules` 与 `ipc-contract`、`app-storage`、`app-layout`、`theme-system`、`ai-tools` 等相关 skill。业务 IPC 复用 `handle` / `unwrap`，前端按 view / composable / service 分层。
